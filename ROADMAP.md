# Дорожная карта disp

Куда развивать диспетчер дальше: значок в трее, приложения для iOS и Android.
Состояние на 2026-11-15, сборка 0.8.003.

## Что есть сейчас

- Хуки Claude Code, Codex и Gemini пишут по файлу на сессию в
  `~/.local/state/disp/`. Все читатели работают с этими файлами напрямую,
  на той же машине.
- `disp watch` — основная панель в терминале: список, лента времени, подписи
  панелей zellij, действия «принять» (`a`), «убрать» (`x`), «перейти» (`g`).
- `disp yes <id>` — ответ агенту «да» из командной строки: Enter в его панели
  zellij.
- Уведомления: рабочий стол (`notify-send`) и Telegram — только в одну
  сторону, без кнопок.
- `disp gui`: графическая оболочка на Slint (пакет `gui/`), в панели
  терминала через term-everything или отдельным окном.

## Главное ограничение

Трей живёт на той же машине и может читать файлы, как `disp watch`. Телефону
файлы недоступны: ему нужны сервис, который отдаёт состояние и принимает
действия, и путь до этого сервиса из сети. Поэтому мобильные приложения
начинаются не с приложения, а с сервиса.

Действие «принять» с телефона — это удалённое управление агентом, который
выполняет команды на твоей машине. Требования к нему не обсуждаются:

- сервис слушает только локальный адрес или частную сеть (Tailscale), не
  интернет;
- на каждый запрос нужен токен;
- перед «да» видно, на что именно соглашаешься: инструмент и команду;
- каждое действие пишется в журнал `events.jsonl` с отметкой, откуда оно
  пришло.

## Этапы

### 1. Значок в трее (Linux)

Самое дешёвое и полезное: видно, кто ждёт, даже когда терминал свёрнут.

- Значок трёх состояний: кто-то ждёт (жёлтый, с числом), есть готовые
  (зелёный), всё спокойно (серый).
- Меню: ждущие сессии с кнопками «Принять», «Перейти», «Убрать»; ниже —
  готовые; внизу — «Открыть панель» (`disp gui --window` или фокус на
  `disp watch`).
- Технически: протокол StatusNotifierItem через D-Bus, крейт `ksni`, без
  GTK. В Ubuntu GNOME такие значки показывает встроенное расширение
  AppIndicator. Данные — те же файлы и та же библиотека `disp`.
- Заодно кнопки прямо в уведомлениях рабочего стола: `notify-send` умеет
  действия (`--action`), и «Да» можно нажать, не открывая ничего.

Проверить заранее: показывает ли твоя оболочка GNOME значки
StatusNotifierItem — расширение AppIndicator должно быть включено.

### 2. Сервис `disp serve`

Основа для всего удалённого.

- Один долгоживущий процесс: следит за каталогом сессий и отдаёт состояние
  (`GET /sessions`, поток изменений по SSE), принимает действия
  (`POST /sessions/<id>/yes`, `/ok`, `/name`).
- Внутри — та же библиотека, что у `disp watch`: правила, сортировка,
  проверка «агент ещё ждёт» перед нажатием Enter.
- Запуск как пользовательский сервис systemd.
- Токен — в `~/.config/disp/env`, как токен Telegram.

### 3. Кнопки в Telegram

Самый быстрый путь на телефон: работает на iOS и Android сразу, без магазинов
приложений.

- К уведомлению «✋ ждёт тебя» добавляются кнопки «Да», «Убрать»,
  «Подробнее».
- Ответы бота принимает `disp serve` (опрос `getUpdates`, без внешнего адреса).
- Принимаются только нажатия из настроенного чата `DISP_TG_CHAT`.

Ограничение: текст уведомления сейчас нарочно без промптов и кода. Чтобы
решать «да» осознанно, нужно показывать команду — значит, она уйдёт в
Telegram. Это решение за тобой.

### 4. Приложение для телефона: сначала веб-приложение (PWA)

Одно приложение на iOS и Android, без магазинов и без аккаунта разработчика
Apple.

- `disp serve` отдаёт ещё и страницу: список, ленты, кнопки. На телефоне она
  ставится на главный экран как приложение.
- Push-уведомления: Web Push работает на Android и на iOS с 16.4 для
  приложений, добавленных на главный экран.
- Доступ — через Tailscale: телефон и машина в одной частной сети, наружу
  ничего не открыто.

### 5. Нативные приложения iOS и Android — если PWA не хватит

Нужны, только если понадобится то, чего веб не умеет: действия прямо на
экране блокировки, виджеты, Live Activities в iOS, надёжная доставка push.

- Варианты:
  - **Tauri 2 + Svelte:** одна кодовая база для трея на десктопе, Android и
    iOS; бэкенд на Rust может встроить библиотеку `disp` напрямую.
  - **Нативно (Kotlin/Compose и Swift/SwiftUI):** лучшее качество на каждой
    платформе, но две кодовые базы.
- Для iOS: аккаунт Apple Developer (99 $ в год) — для TestFlight и push через
  APNs; без него приложение живёт на телефоне 7 дней.
- Push в нативных приложениях идёт через APNs и FCM — нужен сервер с ключами
  или ретранслятор вроде ntfy.

## Порядок и развилки

Рекомендуемый порядок: **трей → `disp serve` → кнопки в Telegram → PWA**,
а нативные приложения — только по итогам PWA.

Решить до начала:

1. Нужен ли macOS. Трей на `ksni` — только Linux; для macOS нужен
   кроссплатформенный крейт (`tray-icon`) или Tauri.
2. Откуда заходить с телефона: только из дома или отовсюду. Отовсюду — значит
   Tailscale или аналог.
3. Какие действия разрешить удалённо: только «убрать» или и «да». «Да» —
   удалённое выполнение команд, см. требования выше.
4. Что делать с оболочкой на Slint (`gui/`), если выбор падёт на Tauri:
   держать обе не имеет смысла.
