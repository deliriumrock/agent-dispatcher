# agent-dispatcher

[English](README.md) · **Українська** · [Русский](README.ru.md)

`disp` — диспетчер сесій AI-агентів: Claude Code, Codex CLI, Gemini CLI.
Одна таблиця на всі відкриті сесії: яка працює, яка чекає на тебе, яка
завершила й чекає, поки ти переглянеш результат.

- Агент сам кличе тебе: сповіщення на робочий стіл або в Telegram, коли він
  уперся в запит дозволу або завершив довгий хід.
- Ніщо не зникає зі списку без явного «прибрати» (`disp ok`, у панелі — `x`).
- Жива панель для zellij: де яка сесія, перехід до неї, відповідь агентові
  «так», стрічка часу. Сесію, що мовчить, перевіряє за процесами: триває довга
  команда, агент завис або його вже немає.
- Агентів у контейнерах теж видно — без хуків і без змін у контейнері.

## Встановлення

Потрібні Linux або macOS і Rust 1.90 чи новіший. Перехід до агента й відповідь
«так» працюють через zellij. Перевірка процесів сесії, що мовчить, читає `/proc`
і є лише на Linux; на macOS така сесія просто «мовчить».

```sh
make install          # ~/.local/bin/disp
disp install claude   # хуки в налаштування агента; так само codex і gemini
disp doctor           # які агенти вже надсилають події
```

Графічна оболонка — окремий пакет, збирається кілька хвилин:

```sh
make install-gui      # ~/.local/bin/disp-gui
disp gui --window     # окремим вікном; без ключа — у панелі термінала через term-everything
```

Значок у треї — на Linux і macOS:

```sh
make install-tray     # ~/.local/bin/disp-tray
disp watch            # панель у терміналі й заодно значок у треї
disp tray             # лише значок; працює у фоні, окремо від термінала
disp tray --autostart # показувати під час входу в систему (--no-autostart — припинити)
```

`disp watch` і `disp gui` самі показують значок, якщо його ще немає. Значок
один на всіх і лишається, коли панель закрито. Не показують, якщо в
налаштуваннях `DISP_TRAY=0`, у сеансі SSH і без робочого столу. Помилки
значка, запущеного так, пишуться в `tray.log` у каталозі стану.

Розмір значка задає панель: у GNOME всі значки AppIndicator малюються у
квадраті 16×16 точок, і плашка значка займає його повністю. Більший — лише
для всіх значків одразу: `gsettings set org.gnome.shell.extensions.appindicator
icon-size 20` (повернути: `gsettings reset … icon-size`).

Значок — плашка (квадрат із заокругленими кутами) з числом сесій, колір за
старшинством: жовтий — стільки чекають на тебе; синій — стільки працюють;
зелений — не працює нічого, стільки готово; сірий — стільки простоюють. Порожня
сіра рамка — відкритих сесій немає. Меню в тому самому порядку, що й таблиця:
«Чекають на тебе», «Працюють», «Простій», «Готово». У кожної сесії кнопки
«Відповісти «так»», «Перейти до панелі», «Прибрати зі списку»; подвійне
клацання по значку відкриває панель. На Linux значок спілкується з оболонкою
через D-Bus (StatusNotifierItem), GTK не потрібен; у GNOME значки показує
розширення AppIndicator. На macOS значок живе в рядку меню, без значка в Dock.

Агентів у контейнерах (dev-контейнери VS Code, Docker, Podman) видно без хуків і
без налаштування самих контейнерів: значок, `disp watch`, `disp gui` і `disp`
самі зазирають у них раз на кілька секунд. У Claude Code видно «працює», «чекає
на дозвіл» і «готово», у Codex — «працює» і «готово»: запитів дозволу Codex у
свій журнал не пише. Сповіщення про такі сесії надсилає той, хто помітив зміну
першим, — зазвичай значок. На Linux у контейнер дивимося через `/proc`, якщо
агента запущено від твого користувача (dev-контейнери так і роблять); інакше й
на macOS — командою `docker exec` або `podman exec`. У колонці ДЕ — `контейнер
<id>`, як у `docker ps`. Вимкнути — `DISP_CONTAINERS=0`.

Агентів, яких запускає сама сесія, видно під її рядком: субагенти Claude Code
(тип і опис завдання) та дочірні агенти Codex (ім'я й завдання). Під рядком — ті,
що працюють, із часом роботи; у подробицях (`disp show`, Enter у панелі) — усі
агенти поточного ходу, завершені позначено ✓; у меню значка — ті, що працюють.
Колонка ПІДЗ рахує агентів, що працюють (`а2`).

Якщо Claude Code завершив відповідь, а його фонова робота ще триває — агенти,
команда (наприклад, тести), монітор чи воркфлоу, — сесію показано як «◐ у фоні»,
а не «готово»: коли робота скінчиться, Claude Code сам продовжить хід, і
сповіщення про кінець прийде тоді, з часом усього ходу. У колонці «ЩО» — чого
сесія чекає, а в команди — сама команда й скільки вона триває. Фонова команда,
яка не завершується сама (сервер), тримає хід не довше порога мовчання: потім
сесія «готово», у сповіщенні — скільки завдань лишилося у фоні.

Налаштування — змінні `DISP_*` в оточенні або у файлі `~/.config/disp/env`:
Telegram (`DISP_TG_TOKEN`, `DISP_TG_CHAT`), поріг сповіщення про кінець ходу
(`DISP_NOTIFY_MIN_SEC`, 120 с), поріг мовчання (`DISP_STALE_MIN`, 30 хв),
підписи панелей zellij (`DISP_PANE_LABEL=1`), спостереження за контейнерами
(`DISP_CONTAINERS`). Повний перелік — у специфікації.

Мова інтерфейсу — англійська, російська або українська: `DISP_LANG=en`, `ru` чи
`uk`. Без нього береться мова системи (`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`,
`LANG`), а якщо вона інша — англійська. Цією ж мовою таблиця, панель, вікно,
значок, довідка і сповіщення, зокрема в Telegram. `disp doctor` показує, яку
мову вибрано.

## Щодня

```sh
disp watch       # жива панель і значок у треї; ? — усі клавіші
disp             # таблиця незакритих сесій
disp show <id>   # промпт, остання відповідь, підзадачі
disp ok <id>     # результат переглянуто — прибрати
disp yes <id>    # відповісти агентові, що чекає, «так»
disp log         # що відбувалося, поки тебе не було
```

## Розробка

```sh
make test   # модульні тести й приймальний набір test.sh
make bump   # номер збірки +1 (0.8.005 → 0.8.006) перед збіркою, яка йде в роботу
```

Стан лежить у `~/.local/state/disp/`. Для дослідів спрямовуй `DISP_STATE_DIR`
і `DISP_CONFIG` у тимчасовий каталог, інакше записи потраплять у справжній
список, і став `DISP_TRAY=0`, інакше `disp watch` покаже в треї ще один значок.
`DISP_CONTAINERS=0` не дасть агентам із контейнерів цієї машини потрапити до
дослідного списку.
