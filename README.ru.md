# agent-dispatcher

[English](README.md) · [Українська](README.uk.md) · **Русский**

`disp` — диспетчер сессий AI-агентов: Claude Code, Codex CLI, Gemini CLI.
Одна таблица на все открытые сессии: какая работает, какая ждёт тебя, какая
закончила и ждёт, пока ты посмотришь результат.

- Агент сам зовёт тебя: уведомление на рабочий стол или в Telegram, когда он
  упёрся в разрешение или закончил длинный ход.
- Ничто не пропадает из списка без явного «убрать» (`disp ok`, в панели — `x`).
- Живая панель для zellij: где какая сессия, переход к ней, ответ агенту «да»,
  лента времени. Молчащую сессию проверяет по процессам: идёт долгая команда,
  агент завис или его уже нет.
- Агенты в контейнерах тоже видны — без хуков и без изменений в контейнере.

## Установка

Нужны Linux или macOS и Rust 1.90 или новее. Переход к агенту и ответ «да»
работают через zellij. Проверка процессов молчащей сессии читает `/proc` и
есть только на Linux; на macOS такая сессия просто «молчит».

```sh
make install          # ~/.local/bin/disp
disp install claude   # хуки в настройки агента; так же codex и gemini
disp doctor           # какие агенты уже шлют события
```

Графическая оболочка — отдельный пакет, собирается несколько минут:

```sh
make install-gui      # ~/.local/bin/disp-gui
disp gui --window     # отдельным окном; без ключа — в панели терминала через term-everything
```

Значок в трее — на Linux и macOS:

```sh
make install-tray     # ~/.local/bin/disp-tray
disp watch            # панель в терминале и заодно значок в трее
disp tray             # только значок; работает в фоне, отдельно от терминала
disp tray --autostart # показывать при входе в систему (--no-autostart — перестать)
```

`disp watch` и `disp gui` сами показывают значок, если его ещё нет. Значок
один на всех и остаётся, когда панель закрыта. Не показывают при
`DISP_TRAY=0` в настройках, в сеансе SSH и без рабочего стола. Ошибки
значка, запущенного так, пишутся в `tray.log` в каталоге состояния.

Размер значка задаёт панель: в GNOME все значки AppIndicator рисуются в
квадрате 16×16 точек, и плашка значка занимает его целиком. Крупнее — только
для всех значков сразу: `gsettings set org.gnome.shell.extensions.appindicator
icon-size 20` (вернуть: `gsettings reset … icon-size`).

Значок — плашка (квадрат со скруглёнными углами) с числом сессий, цвет по
старшинству: жёлтый — столько ждут тебя; синий — столько работают; зелёный —
не работает ничего, столько готово; серый — столько простаивают. Пустая серая
рамка — открытых сессий нет. Меню в
том же порядке, что таблица: «Ждут тебя», «Работают», «Простой», «Готово». У
каждой сессии кнопки «Ответить «да»», «Перейти к панели», «Убрать из списка»;
двойной щелчок по значку открывает панель. На Linux значок говорит с оболочкой по D-Bus
(StatusNotifierItem), GTK не нужен; в GNOME значки показывает расширение
AppIndicator. На macOS значок живёт в строке меню, без значка в Dock.

Агенты в контейнерах (dev-контейнеры VS Code, Docker, Podman) видны без хуков и
без настройки самих контейнеров: значок, `disp watch`, `disp gui` и `disp` сами
заглядывают в них раз в несколько секунд. У Claude Code видно «работает», «ждёт
разрешения» и «готово», у Codex — «работает» и «готово»: запросы разрешения Codex
в свой журнал не пишет. Уведомления о таких сессиях шлёт тот, кто заметил перемену первым, —
обычно значок. На Linux в контейнер смотрим через `/proc`, если агент запущен от твоего
пользователя (dev-контейнеры так и делают); иначе и на macOS — командой `docker exec`
или `podman exec`. В колонке ГДЕ — `контейнер <id>`, как в `docker ps`. Выключить —
`DISP_CONTAINERS=0`.

Агенты, которых запускает сама сессия, видны под её строкой: субагенты Claude Code
(тип и описание задачи) и дочерние агенты Codex (имя и задача). Под строкой — те, что
работают, с временем работы; в подробностях (`disp show`, Enter в панели) — все агенты
текущего хода, законченные отмечены ✓; в меню значка — работающие. Колонка ПОДЗ
считает работающих агентов (`а2`).

Если Claude Code закончил ответ, а его фоновая работа ещё идёт — агенты, команда
(например, тесты), монитор или воркфлоу, — сессия показана как «◐ в фоне», а не
«готово»: когда работа кончится, Claude Code сам продолжит ход, и уведомление о конце
придёт тогда, с временем всего хода. В колонке «ЧТО» — чего сессия ждёт, а у команды —
сама команда и сколько она идёт. Фоновая команда, которая не кончается сама (сервер),
держит ход не дольше порога молчания: потом сессия «готово», в уведомлении — сколько
задач осталось в фоне.

Настройки — переменные `DISP_*` в окружении или в файле `~/.config/disp/env`:
Telegram (`DISP_TG_TOKEN`, `DISP_TG_CHAT`), порог уведомления о конце хода
(`DISP_NOTIFY_MIN_SEC`, 120 с), порог молчания (`DISP_STALE_MIN`, 30 мин),
подписи панелей zellij (`DISP_PANE_LABEL=1`), наблюдение за контейнерами
(`DISP_CONTAINERS`). Полный список — в спецификации.

Язык интерфейса — английский, русский или украинский: `DISP_LANG=en`, `ru` или `uk`.
Без него берётся язык системы (`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`), а если
он другой — английский. На этом же языке таблица, панель, окно, значок, справка
и уведомления, в том числе в Telegram. `disp doctor` показывает, какой язык выбран.

## Каждый день

```sh
disp watch       # живая панель и значок в трее; ? — все клавиши
disp             # таблица незакрытых сессий
disp show <id>   # промпт, последний ответ, подзадачи
disp ok <id>     # результат посмотрел — убрать
disp yes <id>    # ответить ждущему агенту «да»
disp log         # что происходило, пока тебя не было
```

## Разработка

```sh
make test   # модульные тесты и приёмочный набор test.sh
make bump   # номер сборки +1 (0.8.005 → 0.8.006) перед сборкой, которая уходит в работу
```

Состояние лежит в `~/.local/state/disp/`. Для опытов задавай `DISP_STATE_DIR`
и `DISP_CONFIG` во временный каталог, иначе записи попадут в настоящий список,
и `DISP_TRAY=0`, иначе `disp watch` покажет в трее ещё один значок. `DISP_CONTAINERS=0`
не даст агентам из контейнеров этой машины попасть в опытный список.
